# 桌面发送保护：快捷键拦截＋蒙版

状态：供用户评审的设计草案。用户已选择“双入口拦截”方向；用户已确认 macOS 优先；首个应用暂定桌面微信，以下交互尚待评审。本文不是实现完成或兼容性保证。

## 目标与首版范围

在支持的聊天输入框内，鼠标点击发送按钮或按发送快捷键时，先检查当前草稿，提示问题并由用户决定修正、继续发送或取消。校对覆盖中文职场、日常中文、英语和中英混合，分别评价语法错误、歧义和可选润色。

以 macOS 为首发平台，暂以桌面微信为首个适配目标。macOS 最低版本与 Intel／Apple Silicon 支持范围在设备确认后确定。飞书、钉钉按独立适配器后续接入；不宣称覆盖全部客户端、版本或发送入口。不拦截语音、文件、图片或撤回操作。

## 交互契约

1. 用户主动启用目标应用保护。界面显示当前状态：已保护、检查中、需处理、保护不可用；“已保护”只能在输入框、按钮位置、窗口和快捷键模式都被确认后显示。
2. 透明蒙版只接收发送按钮区域的点击，不遮挡其他控件或其他前台应用。焦点、窗口布局或按钮位置无法确认时，立即退出已保护状态，不在旧坐标继续覆盖。
3. 快捷键拦截只对明确匹配的目标窗口和输入框生效。按应用配置分别处理 Return、Command+Return 等候选组合；用户可配置实际发送方式。中文 IME 组合输入时，候选确认与换行必须保留，不能把所有 Enter 都当成发送。
4. 两种入口调用同一个发送请求协调器；检查过程中重复点击或按键不会排队产生多次发送。
5. 检查发现问题时，展示原文片段、说明和修正建议，提供“采纳并重新检查”“仍然发送”“取消”。语气与风格建议为可选项，不冒充客观错误。
6. 检查无问题，或用户明确选择仍然发送时，再次核对会话和草稿。完全匹配后授权一次宿主发送动作，随后重新启用保护；不是检查通过后长期撤掉蒙版。
7. 检查期间文字变化则丢弃旧结果；切换会话则取消待处理请求，禁止把上一会话的发送意图转移到新会话。修改失败时保留草稿并提示，禁止自动清空或自动发送。
8. 网络失败、超时或校对服务不可用时，不自动放行。显示失败原因，让用户选择重试、明确仍然发送或取消。用户始终可以主动暂停保护，暂停状态必须可见。

## 模块与数据流

- 应用适配器：识别受支持的窗口、输入框、会话标识、按钮位置、发送模式；通过系统支持的接口读写草稿并触发宿主发送。优先使用 macOS Accessibility（AXUIElement），是否足够由真机探测决定；蒙版采用透明 NSPanel／NSWindow，快捷键拦截候选为 CGEventTap，均须实际验证。OCR 不作为精确文本回填或校验一致性的依据。
- 输入拦截器：管理按钮覆盖窗口和受限定的快捷键钩子，排除 IME 组合输入，处理前台窗口、缩放、多屏和布局变化。实现方案需先确认能可靠识别组合输入状态。
- 请求协调器：统一鼠标与键盘入口，维护单个活动请求及其状态，拒绝重复发送和过期回调。
- 校对引擎：接收不可变文本快照和场景，返回问题范围、类别、理由和候选修改。云端与本地能力在界面中明确区分；具体模型提供商在实现计划前确定。
- 提示界面：展示问题、确认替换和一次性继续发送操作；管理保护开关及不可用状态。

快照至少包含目标进程和窗口实例、会话身份、编辑框身份、文本版本及原文。授权只对该请求有效，不设置“全局放行 N 毫秒”。若实现不得不短暂移开蒙版或注入输入，必须处理这一空档里的物理输入，先验证不会双发；无法做到时判定该适配路径不可支持。

## 发送状态与边界

状态为：未保护 → 就绪 → 检查中 → 待用户处理／发送前复核 → 一次发送动作 → 就绪。任何身份变化、读取失败或发送状态不确定均取消授权并进入不可用或待确认状态。校对回调必须匹配活动请求和版本。

宿主发送动作的执行与草稿复核无法假定为原子操作。触发成功也不能当作消息送达成功。发送结果不确定时不自动重试，避免重复消息。

系统事件拦截、Accessibility 和覆盖窗口不能构成绝对的发送封锁：应用可能存在未适配入口，进程崩溃或被终止会导致保护消失，系统保护的输入场景、Secure Input、事件监听被系统停用等情况也可能限制能力。首版不通过绕过系统保护或请求 root 权限解决；权限或系统能力不兼容时报告不支持。

本产品定位为用户自愿使用的沟通辅助工具，不以此机制承诺企业强制阻断或不可绕过的防泄漏控制。

## macOS 授权和分发

按所用 API 请求必要的辅助功能授权，以及系统要求时的输入监控授权。分别验证权限未授予、撤销、事件 tap 被停用和应用重启后的行为；权限缺失时不可显示已保护。避免录屏／OCR 路线，不预先申请屏幕录制权限。

全局事件拦截与跨应用控制可能影响 App Sandbox 和 Mac App Store 分发可行性，需依据官方要求核实。暂不承诺上架；直接分发需要后续落实开发者签名、公证和用户安装流程，当前未具备相应证书的证据。

## 隐私与失败处理

默认不保存消息正文或写入遥测。使用云端模型前取得用户明确选择，并告知传输内容与提供商；应用密钥不得打包到客户端。诊断日志仅包含错误码和不含消息内容的状态。

不默认读取整个聊天历史；只读取用户正在校对的草稿。无法可靠取得会话身份或当前文本时，展示不可用并提供用户主动复制校对的降级入口；降级入口不声称具备发送保护。

## 首个技术验证与验收

先在指定 macOS 设备和明确的微信版本完成能力探测，再决定框架与实现计划。当前云环境尚未验证具有 macOS 图形桌面、Xcode 工具链、已登录微信或真机访问能力；不能用 Linux 单元测试代替该验证。

必须验证：

- 精确读取草稿、选区和会话身份；无法做到时停止当前自动发送路线。
- 覆盖窗口随移动、缩放、DPI、多显示器、最小化及前后台切换正确工作，不吞掉其他软件点击。
- 支持的发送模式下，鼠标和快捷键进入同一检查流程；中文候选确认、换行和长按按键不误触发。
- 双击、检查期间继续输入、切换会话、延迟回调、手工修正和引擎超时不会误发或双发。
- 输入修改时保留中文、emoji、多行文本、链接、姓名、金额和日期；替换前确认文本未变化。
- 发送动作失败或结果不确定时不自动重发，助手关闭、崩溃和权限不兼容的保护边界明确可见。

纯逻辑部分后续可测试请求去重、版本失效、授权消费及超时处理；宿主兼容性必须通过真实应用验证，记录 OS、应用版本、发送模式、显示缩放和测试结果。

## 推进条件

下一步由用户评审本设计的交互边界，再形成正式规格及实现计划。若真机验证发现无法准确识别草稿或会话，提出具体受限方案供评审，不以不可靠坐标或 OCR 假装实现可靠保护。
